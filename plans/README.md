## Findings considered and rejected

Recorded so they are not re-audited next run:

- **`computeMetrics` "crash" on `sorted.first()`** (`ScheduleGenerator.kt:144`): safe —
  `groupBy` never produces empty value lists, so the group is always non-empty.
- **`combo.minOf` on empty combo** (`ScheduleGenerator.kt:170`): safe — early-return guards
  ensure `combo` always has ≥1 element.
- **`parseDays` fragility** (`DomainModels.kt:138`): correct — two-letter codes (Tu/Th/Sa/Su)
  are matched before single letters, and it is already covered by `MeetingParsingTest.parsesDayStrings`.
- **Unawaited `loadInstructorRatings`** (`MainViewModel.kt:263`): by design — standard
  `viewModelScope.launch` + `StateFlow` reactive update, not a lost coroutine.
- **`updateAppData` concurrency race**: not a bug — `MutexGuardedStorage.updateAppData`
  serializes read-modify-write under a `Mutex` (`LocalStorage.kt:43-51`). (The narrower
  init-vs-mutation race on in-memory vars *is* real and is plan 006.)
- **Per-row conflict check / generator node-cap "perf" issues**: not worth doing — the
  conflict check is O(slots) of trivial comparisons per card, and the generator is already
  bounded by `MAX_NODES` + `maxResults` + fail-first ordering. No measured cost.
- **`activeSemester` month validation** (`Util.kt:89`): non-issue — the input is the device
  clock (`currentDateInt()`), always a valid date.
- **FileProvider `cache-path "."`** (`file_paths.xml`): low-value hardening — only ICS export
  files (intentionally shared) are cached. Left out.
- **`TimeSlot.overlaps` vs generator `conflictsWith` "inconsistency"**: by design — the UI
  shows hard time overlap; the generator applies the user's optional `minGapMinutes`. Two
  different features, not a bug.
